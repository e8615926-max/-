# Подключение Firebase (бесплатный тариф Spark)

Весь код для Firebase уже есть в игре. Тебе нужно создать проект, включить две бесплатные функции, вставить правила безопасности и вписать два значения в `index.html`. Банковская карта и платёжный аккаунт не нужны, платных функций здесь нет.

Что Firebase даёт игре:
- **Рейтинг** (золото, высота, рубины, кристаллы, кубки; топ-99; карточки игроков) работает везде: из файла, на GitHub Pages, на Firebase Hosting, на любом сайте. Раньше он работал только на claude.ai.
- **Онлайн**: комнаты ищутся через Firebase, а не через сервер PeerJS. Потом игроки соединяются **напрямую друг с другом** (WebRTC), поэтому сама игра почти не тратит лимиты Firebase. Если Firebase недоступен, игра, как раньше, переходит на PeerJS.
- **Вход без регистрации**: каждое устройство автоматически получает анонимный аккаунт Firebase.

Пока два значения не вписаны, Firebase выключен и игра работает как раньше.

## Шаги в консоли Firebase (около 10 минут, можно с телефона)

1. **Создай проект**
   1. Открой https://console.firebase.google.com и войди в свой Google-аккаунт.
   2. Нажми **Create a project** (или **Add project**).
   3. Назови проект, например `wall-play`, и нажми **Continue**.
   4. Если предложат **Gemini in Firebase**, можно не включать.
   5. **Google Analytics** выключи (игре он не нужен). Нажми **Create project**, подожди, потом **Continue**.
   6. Новые проекты создаются на бесплатном тарифе **Spark**: внизу слева в консоли видно **Spark** / **No-cost**. **Никогда не нажимай «Upgrade»** и не привязывай платёжный аккаунт. Без него Firebase не может списать деньги: когда бесплатный лимит кончается, функция просто встаёт на паузу до сброса.

2. **Зарегистрируй веб-приложение (чтобы получить ключ)**
   1. На главной странице проекта нажми значок **Web** `</>` (в блоке «Get started by adding Firebase to your app»).
   2. Название: `Wall Play`. Галочку **«Also set up Firebase Hosting»** не ставь. Нажми **Register app**.
   3. Появится блок `const firebaseConfig = { apiKey: "AIza...", ... }`. Скопируй значение **apiKey** (текст в кавычках после `apiKey:`).
   4. Нажми **Continue to console**. Найти этот блок потом можно здесь: ⚙ **Project settings → General → Your apps → SDK setup and configuration → Config**.

3. **Включи вход без регистрации**
   1. В меню слева: **Build → Authentication** → **Get started**.
   2. Вкладка **Sign-in method** → выбери **Anonymous** → включи **Enable** → **Save**.

4. **Создай базу Realtime Database**
   1. В меню слева: **Build → Realtime Database** → **Create Database**.
   2. **Location** — регион поближе к игрокам (для Европы и России: `europe-west1 (Belgium)`, иначе `us-central1`). Нажми **Next**.
   3. Выбери **Start in locked mode** → **Enable**.
   4. Вверху вкладки **Data** будет адрес базы, например `https://wall-play-1234-default-rtdb.europe-west1.firebasedatabase.app` (или `...firebaseio.com`). Скопируй его **без** косой черты в конце.

5. **Вставь правила безопасности** (они защищают рейтинг и комнаты)
   1. В **Realtime Database** открой вкладку **Rules**.
   2. Удали всё в редакторе и вставь целиком содержимое файла `database.rules.json`.
   3. Нажми **Publish**.

6. **Впиши два значения в игру**
   1. Открой `index.html` в текстовом редакторе и найди `const FIREBASE = {`.
   2. Заполни две строки:
      ```js
      apiKey: 'AIza...твой ключ...',
      databaseURL: 'https://wall-play-1234-default-rtdb.europe-west1.firebasedatabase.app',
      ```
   3. Сохрани файл.

7. **Проверь**
   - Открой игру → **Рейтинг**: после первого забега ты появишься в таблице.
   - **Сеть**: создай комнату на одном устройстве и войди по коду с другого.
   - В консоли, в **Realtime Database → Data**, появятся `board`, `profiles`, а пока открыта комната — `rooms`.

## Обновление правил (ноябрь): защита от спама и сайт на Vercel

1. **Сначала опубликуй новую версию игры**, потом правила. В новых правилах каждый игрок может положить в «почтовый ящик» соединения другого игрока только одно сообщение (раньше — сколько угодно, так можно было забить бесплатный лимит базы). Старые версии игры с новыми правилами в «Сеть» через Firebase не войдут, а новая версия сама приходит к игрокам при следующем открытии.
2. **Realtime Database → Rules** → удали всё → вставь целиком `database.rules.json` → **Publish**.
3. **Authentication → Settings → Authorized domains → Add domain** → `wall-play.vercel.app`.
4. **Google Cloud Console → APIs & Services → Credentials →** Web client → **Authorized JavaScript origins** → `https://wall-play.vercel.app`.
5. Играй и давай ссылку друзьям только на `https://wall-play.vercel.app`. Временные адреса сборок (`wall-play-xxxx-….vercel.app`) у каждой сборки свои: там пустое хранилище браузера, вход Google не работает, а без входа в Vercel их вообще не открыть.

## Вход через Google (включён в игре)

В игре есть вход **через Google** и **как гость**. При первом запуске игра спрашивает, как войти. Гость позже может привязать Google в профиле: прогресс не теряется, аккаунт тот же.

- **Google**: прогресс хранится в базе (`saves/<uid>`), игра запоминает вход, можно играть на нескольких устройствах. Кнопка **«Выйти из аккаунта»** в профиле сначала сохраняет прогресс в облако, потом очищает устройство.
- **Гость**: всё хранится на устройстве, как раньше.
- Если войти в аккаунт Google, где уже есть прогресс, а на устройстве тоже есть свой, игра покажет оба и спросит, какой оставить. Кнопка «назад» оставляет игрока гостем, ничего не меняя.

Что сделать в консоли Firebase (один раз):

1. **Опубликуй новые правила.** В них появилась ветка `saves`: читать и писать своё сохранение может только его владелец. **Realtime Database → Rules** → удали всё → вставь целиком `database.rules.json` → **Publish**. Без этого шага вход через Google работает, но в профиле будет написано «облако закрыто правилами базы».
2. **Разреши сайт, с которого открывается игра.** Окно входа Google работает только на разрешённых адресах: **Authentication → Settings → Authorized domains → Add domain**. Уже разрешены `localhost`, `wall-play-4abb3.firebaseapp.com` и `wall-play-4abb3.web.app`. Если игра лежит на GitHub Pages, добавь `e8615926-max.github.io` (или свой домен). Если домен не добавлен, игра прямо напишет, какой адрес нужно добавить.
3. Вход Google работает, только когда игра открыта **с сайта** (`https://…`). Из файла на телефоне (`file://…`) окно входа открыть нельзя: игра об этом скажет, а гостем можно играть и так.

**Вход прямо в игре (Google One Tap, по желанию).** Обычно вход Google открывает отдельное окно Google. Чтобы вместо этого выезжала панель Google поверх игры (выбрал аккаунт — и всё, без перехода на другой сайт):
1. **Authentication → Sign-in method → Google → Web SDK configuration** — скопируй **Web client ID** (вида `1234…apps.googleusercontent.com`).
2. В `index.html` в блоке `FIREBASE` впиши его в `googleClientId: '…'`.
3. В Google Cloud Console (**APIs & Services → Credentials →** этот Web client) в **Authorized JavaScript origins** добавь адрес сайта игры (например `https://wall-play.vercel.app`).
Если панель не может показаться (браузер её запретил, игрок раньше её закрыл), игра сама откроет обычное окно Google. Полностью «спрятать» вход Google внутрь игры нельзя: выбор аккаунта всегда показывает сам Google — так он защищает пароли. Бесплатно, Spark.

Окно входа делает официальный Firebase Auth SDK (`www.gstatic.com/firebasejs/10.14.1`). Он грузится, только когда игрок открывает экран входа или профиль. Всё это бесплатно на Spark.

## По желанию: бесплатный хостинг на Firebase (нужен компьютер с Node.js)

Получишь ссылку вида `https://wall-play-1234.web.app`. Заодно правила из `database.rules.json` загрузятся сами, и шаг 5 в консоли можно пропустить.

```bash
cd wall-play
npx firebase-tools login            # один раз откроется браузер
npx firebase-tools use --add        # выбери свой проект, имя: default
npx firebase-tools deploy --only hosting,database
```

## По желанию: ограничить ключ

`apiKey` — не секрет: он только называет проект, а защищают данные правила базы. Для дополнительной надёжности:

1. Открой https://console.cloud.google.com/apis/credentials и выбери свой проект.
2. Открой **Browser key (auto created by Firebase)**.
3. В **API restrictions** выбери **Restrict key** и отметь **Identity Toolkit API** и **Token Service API**. Нажми **Save**.

Ограничение «HTTP referrers» не добавляй, если открываешь игру как файл: у файла нет адреса сайта.

## Что проверяют правила (серверная проверка результатов)

- Каждый игрок может писать только свою строку (`board/<uid>`, `profiles/<uid>`), а без входа базу нельзя даже читать.
- Рекорд высоты не растёт быстрее 60 м в секунду, кубки — 100 в секунду, монеты, кристаллы и рубины — тоже с ограничением скорости (по серверным часам с прошлого обновления). Отрицательные и невозможные числа не принимаются, время ставит сервер.
- Кубков не может быть больше, чем «рекорд × число героев» (кубки героя — это его рекорд высоты).
- Новый аккаунт не может сразу записать огромные цифры: первая строка — не больше 1000 м, 3000 кубков, 200 000 монет. Честный игрок с большим прогрессом догоняет свои настоящие цифры сам за минуту-две (игра дописывает их по частям).
- Строку и профиль можно обновлять не чаще раза в секунду (защита от спама в базу).
- Рейтинг читается только как «топ-100 по кубкам»: скачать всю таблицу разом нельзя. Свою строку игрок читать может, чужие — только через топ.
- Чужую открытую комнату занять нельзя. Приглашения в комнату читает только тот, кому они адресованы, и подделать отправителя нельзя.
- Брошенную комнату можно занять снова через 2 часа.
- Друзья и бой 3 на 3: код друга (`fcode`) занимается один раз и только на себя; заявки (`freq`) и приглашения (`inv`) читает только адресат, отправителя подделать нельзя, слать их чаще раза в 2–3 секунды нельзя. Статус «в сети» (`pres`) пишет только сам игрок, весь список разом скачать нельзя. Очередь подбора (`mm3`) читается только как «последние 30»; «забрать команду в бой» (`mm3c`) можно только один раз — второй хост её уже не перехватит.

Ограничение: на Spark нет Cloud Functions, то есть своего серверного кода. Упорный читер может прислать правдоподобные выдуманные числа, но не невозможные.

## Бесплатные лимиты, которые важны (Spark)

| Что | Бесплатно | Что в игре это тратит |
|---|---|---|
| Одновременные подключения к Realtime Database | 100 | Каждый игрок, который сейчас в окне «Сеть» или в онлайн-матче (одно живое подключение). Рейтинг и сохранения — короткие запросы, а не подключения. |
| Место в базе | 1 ГБ | Примерно 1–8 КБ на игрока (строка и профиль). |
| Скачивание из базы | 10 ГБ в месяц | Одна вкладка рейтинга — около 15–25 КБ. Онлайн-матчи через Firebase почти ничего не передают: данные игры идут напрямую между игроками. |
| Друзья и подбор 3 на 3 | — | Без живых подключений: игра коротко спрашивает базу раз в 4–8 секунд (заявки, приглашения), во время подбора — раз в 1,5 секунды. Сам бой идёт напрямую между игроками. |
| Анонимный вход | бесплатно | Один аккаунт на устройство или браузер. |

Если лимит закончится, функция встанет до сброса: рейтинг покажет «Нет связи», а онлайн перейдёт на PeerJS. Денег не спишут никогда.

## Для разработки: локальный эмулятор (проект не нужен)

```bash
npx firebase-tools emulators:start --only auth,database --project demo-wallplay
```

Потом в `index.html` укажи:
`FIREBASE.apiKey = 'demo'`, `FIREBASE.databaseURL = 'http://127.0.0.1:9000'`, `FIREBASE.emu = { auth: 'http://127.0.0.1:9099', ns: 'demo-wallplay-default-rtdb' }`.

Эмулятор работает, только если страница открыта без строки CSP или если в `connect-src` добавлен `http://127.0.0.1:*`.

## Push-уведомления (Firebase Cloud Messaging, версии 104–105)

Код уже в игре (`index.html`, `sw.js`) и на сервере (`api/push.mjs`). Пока не заданы обязательные переменные, кнопка в игре пишет «ещё не настроены», и ничего не ломается.

Что приходит: заявка в друзья и «заявку приняли», раз в день «Новые скины дня» и раз в 3 часа напоминание («Награды тебя ждут!», «Можно крутить колесо!», «Новые квесты!», «Сундук уже готов!», «Победы дня уже обновились!») — на языке игрока, ночью (23:00–8:00 по его часам) напоминания не приходят.

1. **Ключ Web Push (VAPID).** Firebase → ⚙ Project settings → **Cloud Messaging** → внизу **Web configuration → Web Push certificates → Generate key pair**. Скопируй строку **Key pair** (начинается на `B…`).
   Если вверху написано, что **Firebase Cloud Messaging API (V1)** выключен, нажми ⋮ → **Manage API in Google Cloud Console** → **Enable**.
2. **appId.** ⚙ Project settings → **General** → **Your apps** → веб-приложение Wall Play → **appId** (вида `1:629511160238:web:…`).
3. **Ключ сервисного аккаунта (секрет!).** ⚙ Project settings → **Service accounts** → **Generate new private key** → скачается JSON. Никому его не показывай и не клади в репозиторий.
4. **Переменные в Vercel.** vercel.com → проект **wall-play** → **Settings → Environment Variables** → для **Production** добавь:

   | Переменная | Значение | Тип | Обязательна |
   |---|---|---|---|
   | `FIREBASE_SERVICE_ACCOUNT` | всё содержимое JSON из шага 3 целиком (можно и в base64) | Secret — отметь **Sensitive** | **да** |
   | `FCM_VAPID_KEY` | ключ из шага 1 | Config | **да** |
   | `FIREBASE_APP_ID` | appId из шага 2 | Config | **да** |
   | `CRON_SECRET` | любая длинная случайная строка | Secret — **Sensitive** | **да**, иначе не уходят ни «скины дня», ни напоминания каждые 3 часа |
   | `PUSH_ADMIN_KEY` | любой свой длинный пароль | Secret — **Sensitive** | нет — нужен только для ручной рассылки |

   `CRON_SECRET` Vercel сам подставляет в заголовок `Authorization` каждого запуска по расписанию. Без неё сервер отвечает таким запускам 401.

   Необязательные переменные (по умолчанию берутся значения, уже вписанные в игру; задавай, только если они другие):
   - `FIREBASE_SENDER_ID` — Sender ID (Cloud Messaging → Sender ID); если не задан, берётся из `FIREBASE_APP_ID`;
   - `FIREBASE_API_KEY` — Web API Key (General → Web API Key);
   - `FIREBASE_DB_URL` — адрес Realtime Database.

   Потом **Deployments → последняя → ⋮ → Redeploy**: переменные начинают действовать только после новой выкладки.
5. **Правила базы.** Realtime Database → Rules → удали всё → вставь **целиком** текущий `database.rules.json` → **Publish**. В ветке `push` в версии 105 появились поля `r` (напоминания вкл/выкл) и `z` (часовой пояс). **Если ты уже публиковал правила версии 104 — опубликуй заново**: со старыми правилами игра v105 не сможет включить уведомления (лишние поля запрещены).
6. **Ограничения API-ключа (если ставил).** Google Cloud Console → **APIs & Services → Credentials** → Web API Key (Browser key). Если у ключа есть ограничения:
   - **Website restrictions** — должен быть `https://wall-play.vercel.app/*`;
   - **API restrictions** — разреши ещё **Firebase Installations API** и **Firebase Cloud Messaging API** (без них телефон не получит токен).
   Если ограничений нет — ничего делать не нужно.
7. **Проверь.** Открой `https://wall-play.vercel.app/api/push?cfg=1`: там должно быть `"on":true` (браузер может до 5 минут показывать старый ответ — обнови страницу позже или открой в режиме инкогнито). На Android в Chrome: игра → ≡ → **Уведомления** → **Включить** → разреши. Закрой игру и попроси друга отправить тебе заявку по Wall Play ID: придёт уведомление.

**Расписание** (`vercel.json` → `crons`, время UTC; на бесплатном тарифе Vercel каждое расписание — раз в сутки и может сработать в любую минуту своего часа):
- «Новые скины дня» — 15:07 UTC (18:07 по Москве);
- напоминания — 8 расписаний в :17 каждого третьего часа: 00, 03, 06, 09, 12, 15, 18, 21 UTC. Сообщения идут по кругу, у каждого игрока на его языке; ночью по его часам — пропуск. Выключить: в игре ≡ → Уведомления → «Напоминания».

**Ручная рассылка всем** (новость, событие; нужен `PUSH_ADMIN_KEY`), например из терминала:
```
curl -X POST https://wall-play.vercel.app/api/push \
  -H "Authorization: Bearer ТВОЙ_PUSH_ADMIN_KEY" -H "Content-Type: application/json" \
  -d '{"title":"Wall Play","body":"Новое событие уже в игре!"}'
```
Одному игроку: добавь `"uid":"<uid игрока>"`.

Ограничения: на iPhone уведомления работают только если игра добавлена на экран «Домой» (iOS 16.4+) и открыта оттуда; в обычном Safari — нет.
